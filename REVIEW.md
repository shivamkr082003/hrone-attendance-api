| 1 | module, L22 | `MongoClient` is created without `tz_aware=True`, so every BSON date comes back as a **naive** datetime. ## Looked at and decided were not defects

- `load_dotenv()` (L20): by default it does **not** override variables already set in the environment, so real env vars win, as the contract requires. Kept.
- `IST = timezone(timedelta(hours=5, minutes=30))` (L25): correct, India has no DST.
- `doc.pop("_id", None)` after `insert_one` in `create_employee`: correct, because `insert_one` adds `_id` to the dict. I now build the response with `employee_out` anyway.
- Filtering dates with `$gte` / `$lte` on `"YYYY-MM-DD"` strings (L136-141): correct, because zero-padded ISO dates sort lexicographically in calendar order, and they can use the `(emp_code, date)` / `(date, emp_code)` indexes.
- The `{"_id": 0}` projection in `list_employees` is fine; I kept it.
- The helper functions were worth reusing, but not as they were: their signatures did not carry enough information (no attendance date for late, no overnight info for overtime), so I rewrote them around `shift_window(date, employee)`.
